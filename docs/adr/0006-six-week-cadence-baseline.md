# ADR-0006 Train0 = 6×1 周、W1 起 2026-11-09 的节奏基线

- 状态：已接受
- 日期：2026-11-18（回填；计划 v1.0 冻结于 2026-11-05）
- 决策者：Train0 团队（PO 批准）
- 影响面：计划文档、每周 Demo、DoD 时间点、外部依赖假设
## 背景（为什么现在必须有决定）

六周 Train 的排期已经进入第 2 周，但"周"到底从哪天算、缓冲放在哪、计划冻结后能不能改，
散落在计划的不同段落里。没有一条固定基线，任何一次延期都会被解释成"计划本来就没定"，
周报也无法对齐。计划本身只写计划，不写进度（见 ADR-0007），所以更需要把节奏单独固化。
## 决策（一句话 + 3–6 条具体条款，可判定）

一句话：Train0 是 6 个 1 周 Sprint，W1 从 2026-11-09 起，计划冻结后只改勘误不改日期。

1. 周期为 6 个 Sprint × 1 周；W1 2026-11-09~11-13，W2 11-16~11-20，W3 11-23~11-27，
   W4 11-30~12-04，W5 12-07~12-11，W6 12-14~12-18。
   检查点：周报/分支 tag 的周号与日期能按此表对上。
2. 最后 2 天为缓冲，不排新功能；缓冲用于补验收与文档，不用于加需求。
   检查点：W6 只做收尾与 Demo。
3. Demo 固定在 W6 最后一天（2026-12-18）；每周 Demo 在周末。
   检查点：demo tag 见 ADR-0008。
4. 计划版本 v1.0（2026-11-05）冻结：日期、范围、DoD 不得就地改；发现笔误只能走勘误，
   并在 `docs/backlog.md` 登记来源行。
   检查点：计划 diff 不出现日期与范围变更。
5. 计划文件不写状态：不勾复选框、不贴提交号、不写"已完成"。
   检查点：计划全文 0 个复选框。
6. 若启动日假设不成立（A8），整体平移，不压缩周数。
   检查点：平移决定必须新写 ADR 取代本文件。
## 替代方案与被否原因（≥1 条，写清代价）

- **3 个 2 周迭代**：反馈周期翻倍，六周只有 3 次 Demo，问题暴露太晚；每周 Demo 的
  仪式感消失后，进度压力会集中到最后一周。
- **按功能排期、不设固定周**：无法回答"现在第几周、还剩几周"，DoD 时间点失效。
- **把进度写进计划、每周更新计划**：已证明会漂移（计划 0 复选框，进度另记在
  `verification/TEST-PLAN.md` 的散段里），且计划一旦成为"活文档"，范围就会随之膨胀。
## 后果（正面/负面/需要配套的动作）

正面：周号可判定、Demo 有固定节奏、延期有唯一处理方式（整体平移）。

负面：一周粒度对小团队切换成本高，跨周任务（E8 接线）容易被切成两半；
最后 2 天缓冲一旦被占用，验收就会挤压到 W6 之后。

配套动作：每周 Demo 后按 ADR-0008 打 tag；进度写 `docs/STATUS.md`；
计划的位置与单一入口见 ADR-0010。
