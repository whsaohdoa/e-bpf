# Runbooks

本目录存放**可复现的运维/一次性操作手册**：照着步骤执行即可得到确定结果，执行者不需要临场判断。

## 与 PROCESS.md 的分工

- `docs/PROCESS.md`：长期协作流程（分支、PR、评审、发布、状态更新），回答“平时怎么做”。
- `docs/runbooks/`：一次具体操作（清理、加固、迁移、故障处置），回答“这次做什么、做完怎么证明、出错怎么退”。
- 两者冲突时以 PROCESS.md 的流程为准；runbook 只补充命令、顺序和回滚，不重新定义流程。

## 每个 runbook 必须包含

1. **前置条件**：权限、工具、仓库状态、备份是否就绪。
2. **影响面**：会改什么、谁受影响、是否可逆。
3. **步骤**：可直接复制执行的命令，注明工作目录。
4. **验证**：命令与预期输出，不接受“看起来正常”。
5. **回滚**：逐步可逆；不可逆处必须提前备份。
6. **是否已执行**：`未执行` / `已执行 YYYY-MM-DD by <name>`，执行后回填。

## 约定

- 文件名 `NN-主题.md`，编号只用于排序。
- 命令默认 bash（Git Bash 或 Linux 容器）；Windows 宿主路径写成 `/d/repos/...`。
- 涉及删除、权限、远端分支的步骤，先给 dry-run，再给执行命令。
- 执行后回填“是否已执行”和验证输出；命令变更时同步改 runbook。
- 文档只保留单一来源，不要在工作区外层或其它目录复制一份。
